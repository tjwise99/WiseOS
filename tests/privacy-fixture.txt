Positive control for scripts/check-privacy.sh.

Written from how a secret would actually get committed, and the patterns written
to match this — not the other way round. Deriving the specimen from the regex is
how the SSID hole got in: the pattern required a dot after `networks`, the
specimen was written to have one, and both agreed nothing was wrong while
`networking.wireless.networks = { "My Home 5G" = { }; }` went straight through.

Excluded from the real scan. The check asserts every pattern matches something
here, through the same pathspec the real scan uses — so a broken pathspec fails
the control instead of quietly scanning nothing.

Invented values, matched by shape alone.

  # wireless, as an attrset of networks rather than a dotted path
  networking.wireless.networks = { "My Home 5G" = { psk = "example-not-real"; }; };
  networking.wireless.networks."Cafe WiFi".pskRaw = "0011aabb";
  SSID = "ExampleNet";
  ssid=ExampleNet

  # iwd, which is what this host actually runs: /var/lib/iwd/<SSID>.psk
  [Security]
  Passphrase=example-not-a-real-key

  # hostapd
  wpaPassword = "example-not-a-real-key";

  # accounts
  users.users.example.password = "example-not-a-real-password";
  users.users.example.hashedPassword = "$6$example$notarealhash";
  "hashedPassword" = "$6$example$notarealhash";
  initialPassword = "example-not-the-placeholder";

  # machine identity

  macAddress = "de:ad:be:ef:12:34";
