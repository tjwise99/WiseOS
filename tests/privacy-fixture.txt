Positive control for scripts/check-privacy.sh.

Written from how a secret would actually get committed, and the patterns written
to match this — not the other way round. Deriving the specimen from the regex is
how the SSID hole got in: the pattern required a dot after `networks`, the
specimen was written to have one, and both agreed nothing was wrong while the
attrset form went straight through.

Every check in the script must match something here, through the same pathspec
its real scan uses. Each check is one shape, never an alternation, so one
specimen per check actually covers that check — an alternation would let a dead
branch hide behind a live sibling, which is how four wireless spellings went
unguarded.

Excluded from the real scan. Invented values, matched by shape alone.

  # --- wireless, in the forms a person writes them -----------------------
  networking.wireless.networks = { "My Home 5G" = { psk = "example-not-real"; }; };
  networking.wireless.networks."Cafe WiFi".pskRaw = "0011aabbccdd";
  SSID = "ExampleNet";

  # iwd, which is what this host runs: /var/lib/iwd/<name>.psk
  [Security]
  Passphrase=example-not-a-real-key

  # hostapd
  wpaPassword = "example-not-a-real-key";

  # --- accounts ----------------------------------------------------------
  users.users.example.password = "example-not-a-real-password";
  users.users.example.hashedPassword = "$6$example$notarealhash";
  users.users.example.initialHashedPassword = "$6$example$notarealhash";
  initialPassword = "example-not-the-placeholder";

  # A full-length crypt hash — the crypthash value shape, which the two option
  # checks above miss when the hash is loose: pasted into prose, or written into
  # a `pkgs.writeText` rather than assigned to a hashedPassword* option.
  loose = "$6$abcdefghijklmnop$0123456789abcdef0123456789abcdef0123456789abcdeXYZ";
